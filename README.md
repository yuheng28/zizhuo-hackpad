## Overview

ZizhuoPad is a custom mechanical macropad with 6 keys and an OLED display.

It is designed to allow for easy hotswapping of the switches, and (maybe not as easy) key mapping modifications.

## Rationale

This is a project to build a custom mechanical macropad. The purpose of this project is to create a birthday gift for my friend, after whom this project is named.

As a technical challenge, I opted to write the firmware using AVR-C, instead of using Arduino or QMK. The PCB was designed using KiCAD, and the case was designed using Fusion 360.

## Hardware Summary

### Electronics
- Microcontroller: SparkFun Pro Micro (ATmega32U4)
- OLED Display: 128x32 pixel display
- Switches: 6 hotswappable mechanical switches (Akko Piano Switches)
- Connector: USB-C

### Case
- Material: PETG
- Infill: 75%
- Walls: 10 for Case, 5 for Lid
- Layer Height: 0.2mm

## Modifying the Software

In the `firmware` directory, a Microchip Studio project is included. You can open the `.atsln` file in Microchip Studio to build the firmware.

The firmware uses the LUFA library to implement USB HID functionality. The project was first developed using the LUFA library's keyboard example, so as to have the build environment set up and working. Then, the code was modified to implement the desired functionality for the macropad.

However, since these are all in the project files, the build environment is already set up and working.

To modify the key mappings, lines 292-325 in Keyboard.c can be modified by replacing the keycode macros with the appropriate keycodes from LUFA's HID usage tables.

To modify the animation on the OLED display, the lines 65-135 in OLED.c can be modified with the appropriate bytes to display the desired animation. The OLED display has a resolution of 128x32 pixel display. To generate the byte array for the animation, use [Javl's image2cpp tool](https://javl.github.io/image2cpp/). The relevant settings for the tool are:
- Canvas Size: 128x32
- Orientation: Vertical
- Invert pixels: Yes (alternatively, line 191 in Keyboard.c can be commented to invert the pixels)

The other settings can be left as their default values. The generated byte array can then be copied into lines 292-325 in Keyboard.c.

After building the firmware, the resulting `Keyboard.hex` file can be flashed to the ATmega32U4 microcontroller using avrdude.

To flash the microcontroller, it needs to first be put into bootloader mode. This can be done by shorting the reset pin to ground. For approximately 8 seconds after doing this, the microcontroller will be in bootloader mode and can be flashed using avrdude.
